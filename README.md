# Markdown Editor - 技術ブログ開発メモ

## 概要

Next.js で構築した技術ブログの開発課題として、マークダウンエディタ機能を実装する。  
コンテンツ管理には microCMS の公開 API を利用する。編集対象は 1 記事に限定し、シンプルな構成で早期実装を目指す。

---

## 背景・方針

- Next.js 技術ブログ開発の 1 課題として、マークダウンエディタを実装する
- コンテンツ管理には microCMS を採用し、公開 API 経由で記事データを取得・更新する
- 編集できるブログは microCMS 上の 1 記事に限定する
- 下書き機能は今回のスコープに含めない（microCMS では draftKey を API 経由で取得できないため）
- 機能を制限した分、セキュリティ（XSS 対策など）を重点的に強化する
- Firestore の利用は次回スコープに持ち越す

## MVP ロードマップ

### MVP 1：画面の骨格を作る

- トップページにマイブログ見出しを作る
- マイブログ記事カードを 1 件表示する（内容はダミー）
- 記事参照画面・編集画面のルーティングを設定する

### MVP 2：編集機能を実装する

- マークダウンエディタを実装する（左：エディタ／右：プレビュー）
- タイトル編集フォームを実装する
- 公開ボタンを実装する（確認メッセージ → OK で microCMS に反映）

### MVP 3：microCMS 連携

- microCMS の公開 API を利用して記事データを取得・表示する
- 記事一覧・記事参照画面で microCMS のデータを表示する
- 編集内容を microCMS に書き込む（Content Management API 利用）

### MVP 4：画像アップロード

- 画面キャプチャの貼り付けで、画像を Firebase Storage に保存・取得する（容量制限あり）

### MVP 5：セキュリティ強化

- マークダウンレンダリング時の XSS サニタイズ対応（DOMPurify 等）
- Firebase Storage のアップロードバリデーション（ファイルサイズ・拡張子）

### ✅ 今回のスコープ

- トップページにマイブログ見出しを作る
- マイブログ記事カードを 1 件表示する（microCMS から取得）
- マイブログ記事カードをクリックすると詳細表示画面へ遷移
- マイブログ記事詳細表示画面構成
  - タイトル
  - 更新日
  - 本文
  - 編集ボタン（クリックするとマイブログ記事編集画面へ遷移）
- マイブログ記事編集画面構成
  - タイトル編集フォーム
  - マークダウンエディタ（画面左）
  - プレビュー（画面右）
  - 公開ボタン（確認メッセージ → OK で microCMS に反映）
- マークダウンエディタの実装
- 記事内容を microCMS から取得・更新
- 記事内画像を Firebase Storage に保存（容量制限あり）
- 誰でも編集可能（認証なし）
- XSS 対策などセキュリティの強化

> **注意**：下書き保存機能は今回のスコープ外。microCMS の draftKey は API 経由で取得できないため、編集内容は公開ボタン押下時に直接 microCMS へ反映される。

### 残課題

- 下書き機能（microCMS の draftKey 運用の検討、または Firestore への下書き保存）
- エディタの画像挿入時と undo / redo（CodeMirror への移行が必要かも）
- Firestore の導入（次回スコープ）

### ✅ 画面設計

#### 画面構成

| 画面         | URL（予定）          | 説明                                     |
| ------------ | -------------------- | ---------------------------------------- |
| トップページ | `/`                  | 「マイブログ」タイトルで記事カードを表示 |
| 記事参照画面 | `/myblogs/{id}`      | 記事カードをクリックすると本文を表示     |
| 編集画面     | `/myblogs/{id}/edit` | Qiita 風マークダウンエディタ             |

#### 画面遷移・操作フロー

```
トップページ（記事カード）
  └── 記事カードをクリック
        └── 記事参照画面
              └── 右上「編集」ボタンをクリック
                    └── 編集画面（マークダウンエディタ）
                          └── 「公開」ボタン
                                └── microCMS に反映
```

## セキュリティ方針

機能をシンプルに絞った分、セキュリティを重点的に対応する。

- **ストレージ**：アップロード前にファイルサイズ・拡張子をバリデーション
- **microCMS API キー**：書き込み権限を持つ API キーはサーバーサイドのみで使用し、クライアントに露出させない

---

## データ設計

### microCMS

編集対象は microCMS 上の 1 記事に限定する。

```
記事ドキュメント（microCMS）
  ├── title: "記事タイトル"
  ├── content: "本文（Markdown）"
  ├── createdAt: timestamp（自動付与）
  └── updatedAt: timestamp（自動付与）
```

- 取得：`GET /api/v1/myblogs/{id}`（公開 API）
- 更新：`PATCH /api/v1/myblogs/{id}`（Content Management API、サーバーサイドのみ）

### Firebase Storage

```
/image/{ファイル名}  # 記事内画像
```

### Firestore（次回スコープ）

下書き管理や閲覧ログなど、microCMS では対応しにくい用途での活用を検討する。
